## 二、技术方案

### 扫码登录完整流程

```
前端(PC/网页)              后端(IntelliConnect)              微信服务器
     │                           │                              │
     │── GET /wxScanLogin/qrcode ──→│                           │
     │                           │── getCachedAccessToken() ──→│
     │                           │←── access_token ────────────│
     │                           │── createTempQrCode() ──────→│
     │                           │←── ticket + url ────────────│
     │                           │  Redis: sceneId → "waiting"  │
     │←── {qrCodeUrl, sceneId} ──│                              │
     │                           │                              │
     │ [展示二维码给用户扫描]     │                              │
     │                           │                              │
     │                    [用户微信扫码]                         │
     │                           │←── POST /wxmsg (事件推送) ──│
     │                           │  解析 subscribe/SCAN 事件     │
     │                           │  提取 sceneStr + openid       │
     │                           │  Redis: sceneId → openid      │
     │                           │── 回复"扫码登录成功" ──────→│
     │                           │                              │
     │── GET /wxScanLogin/check ──→│                            │
     │   (轮询，每2-3秒一次)      │  检查 Redis sceneId 的值    │
     │                           │  值为 openid → 登录成功       │
     │                           │  查找/创建 wx_user            │
     │                           │  颁发 JWT token               │
     │←── {status, token} ───────│                              │
     │                           │                              │
     │ [存储 token，跳转主页]     │                              │
```

### 微信事件处理（两种场景）

| 场景 | 微信事件 | EventKey 格式 | 处理方式 |
|------|----------|---------------|----------|
| 新用户首次扫码并关注 | `subscribe` | `qrscene_{sceneStr}` | 去掉前缀后匹配 Redis |
| 已关注用户扫码 | `SCAN` | `{sceneStr}`（无前缀） | 直接匹配 Redis |

### 消息格式支持

公众号事件推送可能以 JSON 或 XML 格式发送，代码中两种格式都已处理：
- **JSON 格式**：小程序客服消息场景
- **XML 格式**：公众号标准事件推送场景（扫码登录主要走这条路径）

## 四、API 接口文档

### 4.1 生成扫码登录二维码

```
GET /wxScanLogin/qrcode
```

**权限**：无需认证（公开接口）

**响应示例**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "qrCodeUrl": "https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=xxx",
    "sceneId": "a1b2c3d4e5f6...",
    "expireSeconds": 300
  }
}
```

### 4.2 检查扫码登录状态

```
GET /wxScanLogin/check?sceneId={sceneId}
```

**权限**：无需认证（公开接口）

**响应状态说明**：

| status | 含义 | token 字段 |
|--------|------|-----------|
| `waiting` | 等待用户扫码 | null |
| `scanned` | 用户已扫码，登录成功 | Bearer JWT |
| `expired` | 二维码已过期 | null |

**响应示例（已扫码）**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "status": "scanned",
    "token": "Bearer eyJhbGciOiJIUzI1NiJ9...",
    "isNewUser": true
  }
}
```

## 五、Redis Key 设计

| Key 格式 | 值 | TTL | 说明 |
|----------|-----|-----|------|
| `wx_scan_login:{sceneId}` | `"waiting"` | 300s（可配置） | 二维码已生成，等待扫码 |
| `wx_scan_login:{sceneId}` | `"{openid}"` | 继承原有 TTL | 用户已扫码，存入 openid |
| `wx_access_token:{appid}` | `"{access_token}"` | 7000s | 公众号 access_token 缓存 |

## 六、前端对接指引（待实现）

前端接入扫码登录需要：

1. **登录页新增"微信扫码登录"选项卡**
2. **调用 `GET /wxScanLogin/qrcode`** 获取二维码 URL 和 sceneId
3. **展示二维码**（可用 `<img>` 直接加载 qrCodeUrl）
4. **启动轮询**：每 2-3 秒调用 `GET /wxScanLogin/check?sceneId=xxx`
5. **处理轮询结果**：
   - `waiting`：继续轮询
   - `scanned`：保存 token 到 localStorage，跳转主页
   - `expired`：提示过期，提供"刷新二维码"按钮
6. **超时处理**：300 秒后停止轮询，提示重新获取二维码

## 八、注意事项与后续计划

### 微信公众号要求

1. **需要认证服务号**：带参二维码 API 需要已认证的服务号才能调用
2. **回调地址配置**：微信公众号后台需要配置服务器地址为 `fu.fans.market`，Token 为 `daxiangwawa666888`
3. **消息加解密方式**：当前使用明文模式，如需安全模式需要配置 EncodingAESKey

### 与原有功能的兼容

- 扫码登录与原有小程序登录**互不影响**，使用不同的端点
- 扫码登录创建的是 WxUserEntity（与小程序登录相同的用户表），openid 基于公众号 appid
- 同一个微信用户在公众号和小程序中的 openid 不同，需要通过 unionid 关联（当前未实现）
