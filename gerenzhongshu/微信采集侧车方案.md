## 一、背景与定位

微信采集侧车（Sidecar）是一个独立于 IntelliConnect 主系统的轻量服务，负责从微信个人号/群聊中提取消息，并通过主系统的**统一输入 API**（`POST /api/v2/input/messages`）写入。

### 核心原则

1. **主系统不接触微信底层协议** - 侧车封装所有微信协议细节
2. **侧车只调统一输入 API** - 不直写知识库、记忆、同步等内部接口
3. **两层独立部署、独立升级** - 侧车挂掉不影响主系统运行

### 当前微信能力分层

| 层级 | 入口 | 负责人 | 说明 |
|------|------|--------|------|
| 公众号官方回调 | `Wx.java /wxmsg` | 主系统 | subscribe/SCAN/文本/图片/语音 |
| 公众号扫码登录 | `Wx.java /wxScanLogin/*` | 主系统 | 已实现 |
| 小程序登录 | `Wx.java /wxLogin` | 主系统 | 已有 |
| **个人号消息采集** | **侧车服务** | **侧车** | **本方案范围** |

## 二、技术选型

### 短期方案（推荐先用）

| 方案 | 说明 | 风险 |
|------|------|------|
| **itchat / wechaty** | 基于网页微信协议的 Python/Node 库 | 微信官方已大面积封禁网页端登录 |
| **hook 注入方案** | Windows 微信客户端 hook（如 wxbot、wcferry） | 需要 Windows 环境，稳定性依赖第三方 |
| **企业微信 API** | 已有企业微信配置（CorpID/AgentId） | 仅限企业微信场景，不能抓个人微信消息 |

**短期建议**：先用企业微信 API 做消息桥接测试（已有凭据），验证主系统统一输入 API 链路；个人微信采集方案后续评估。

### 中期方案

根据微信生态变化选择：
- 如果企业微信够用 → 持续使用企业微信 API
- 如果需要个人微信 → 评估 wcferry 等方案的稳定性
- 如果转向其他平台 → 统一输入 API 天然支持多来源

## 三、侧车 → 主系统接口规范

### 3.1 鉴权方式

侧车调用主系统 API 必须携带有效 JWT Token：

```
Authorization: Bearer <JWT_TOKEN>
```

**获取方式**：
- 方案 A：为侧车创建专用系统账号，通过 `POST /api/v2/login` 获取 JWT
- 方案 B：配置长期有效的 Service Token（需要主系统扩展）

**短期用方案 A**，创建一个 `sidecar-wx` 账号即可。

### 3.2 消息签名（防篡改）

短期阶段 JWT 鉴权即可，不额外做消息签名。

中期如果侧车部署在外网，建议增加：
- 请求体 HMAC-SHA256 签名
- 签名密钥在主系统和侧车各持一份
- 主系统在 `InputController` 入口验签

### 3.3 防重（去重机制）

统一输入 API 已内置 `dedupeKey` 字段：

```json
{
  "dedupeKey": "wechat:wxid_xxx:1710589200:msg_12345"
}
```

**去重键生成规则**：`{sourceType}:{senderId}:{timestamp}:{原始消息ID}`

主系统 `InputMessageServiceImpl.createMessage()` 内部已按 `dedupeKey + createdBy` 做唯一性校验，重复消息返回已有记录而不报错。

### 3.4 失败重试

| 场景 | 重试策略 |
|------|----------|
| 网络超时 | 侧车端指数退避重试，最多 3 次 |
| 主系统 5xx | 同上 |
| 主系统 4xx（参数错误） | 不重试，记录到侧车本地日志 |
| JWT 过期（401） | 自动重新登录获取新 JWT，然后重试 |
| 去重冲突（200 但返回已有记录） | 视为成功，不重试 |

## 四、侧车发送的消息格式

对应 `InputMessageCreateParam`：

```json
{
  "sourceType": "wechat",
  "sourceAccountId": "wxid_sidecar_bot",
  "sessionId": "group_12345678",
  "senderId": "wxid_sender_xxx",
  "contentType": "text",
  "rawContent": "这篇文章不错 https://mp.weixin.qq.com/...",
  "normalizedContent": "这篇文章不错",
  "attachments": [
    {
      "type": "url",
      "url": "https://mp.weixin.qq.com/...",
      "fileName": null,
      "mimeType": "text/html",
      "size": null
    }
  ],
  "dedupeKey": "wechat:wxid_sender_xxx:1710589200:msg_99887766",
  "receivedAt": "2026-03-16T19:30:00+08:00"
}
```

### contentType 映射

| 微信消息类型 | contentType | 说明 |
|-------------|-------------|------|
| 文本消息 | `text` | rawContent = 原文 |
| 链接/文章 | `url` | rawContent = 标题+摘要，attachments 带 URL |
| 图片 | `image` | rawContent = "[图片]"，attachments 带图片 URL |
| 语音 | `audio` | rawContent = "[语音]"，attachments 带音频 URL |
| 视频 | `video` | rawContent = "[视频]"，attachments 带视频 URL |
| 文件 | `file` | rawContent = 文件名，attachments 带文件 URL |

## 五、侧车部署架构

```
┌──────────────────┐     HTTPS + JWT     ┌──────────────────────┐
│  微信采集侧车    │ ─────────────────→  │  IntelliConnect 主系统│
│  (独立进程/容器) │   POST /api/v2/     │  (ic.fans.market)     │
│                  │   input/messages     │                       │
│  - 微信协议适配  │                     │  - InputController    │
│  - 消息格式转换  │  ←── 200 / 4xx ──  │  - InputMessageService│
│  - 本地重试队列  │                     │  - 知识库/记忆/同步   │
└──────────────────┘                     └──────────────────────┘
```

## 七、安全注意事项

1. **侧车 JWT 权限最小化** - 侧车账号只需要调用 `/api/v2/input/messages` 的权限
2. **不要把侧车的微信登录态暴露到公网** - 侧车只监听，不对外提供接口
3. **消息内容加密存储** - 如果消息含敏感信息，考虑 `rawContent` 字段加密
4. **定期轮换 JWT** - 侧车每次启动重新获取 JWT
